# SupplyAI AI 决策卡片方案

更新时间：2026-05-17

## 1. 目标

AI 对话不再只输出长段自然语言。涉及库存风险、补货建议、采购计划、大促备货、规则模拟等业务决策时，优先用结构化“决策卡片”呈现。

目标是让业务用户一眼看到：

- 当前结论
- 关键数字
- 计算依据
- 推荐动作
- 是否需要二次确认

## 2. 当前实现状态

当前前端已先实现一版“自然语言解析成卡片”的验证方案：

- 后端 AI 文本可以流式返回。
- 前端累加文本内容。
- 当前端识别到 FBA 可售天数、预计断货时间、建议采购量等关键字段后，将文本转换为卡片。
- 该方式适合验证视觉与交互，但不适合作为长期协议。

当前卡片已覆盖单 SKU 补货场景：

- P1 紧急风险
- FBA 可售天数
- 预计断货日期
- 建议采购数量
- 预计采购额 / 金额待确认
- 覆盖周期需求
- 当前总库存
- 需求缺口
- 向上取整规则
- 生成采购计划动作

## 3. 推荐正式方案

正式方案应改为后端返回结构化 `card`，前端按 `card.type` 渲染对应卡片。

AI 自然语言只负责解释，不负责计算、不负责排版、不重新推导采购量。

推荐链路：

```text
用户提问
→ 前端显示分析中状态
→ 后端 Tool 执行确定性计算
→ 返回结构化 card
→ 前端立即稳定展示关键数字
→ AI summary / explanation 流式输出补充说明
```

## 5. 推荐卡片类型

当前实施优先级：

1. 高风险 SKU 队列
2. 节日 / 大促备货
3. 单 SKU 补货决策
4. 运输方案对比
5. 规则影响模拟

| 场景 | card.type | 重点展示 |
| --- | --- | --- |
| 单 SKU 补货决策 | `replenishment_decision` | FBA 可售、断货日、建议采购量、金额、计算依据 |
| 高风险 SKU 队列 | `risk_queue` | P1/P2/P3 数量、Top SKU、预计断货、建议动作 |
| SKU 详情解释 | `sku_detail_explain` | 风险原因、库存拆解、销量依据、规则依据 |
| 节日 / 大促备货 | `holiday_readiness` | 节日日期、关联 SKU、销量系数、备货缺口 |
| 运输方案对比 | `plan_comparison` | 海运 / 空运 / 混合方案的到货时间、成本、断货风险 |
| 规则影响模拟 | `rule_impact` | 调整前后安全天数、采购量、采购时间变化 |
| 新品判断 | `new_product_review` | 样本天数、销量趋势、是否继续补货、数据不足提示 |
| 管理摘要 | `management_summary` | 今日风险、资金占用、需决策事项、异常提醒 |
| 数据质量问题 | `data_quality` | 缺失字段、影响范围、是否可继续计算 |
| 采购计划确认 | `purchase_confirmation` | SKU、数量、供应商、金额、二次确认 |

## 6. 前端渲染规则

每类卡片统一分为四层：

1. 结论区：风险等级、标题、最终建议。
2. 关键指标区：3-5 个业务用户最关心的数字。
3. 依据区：公式拆解、库存拆解、销量依据、规则依据。
4. 动作区：只放当前场景最关键动作，避免按钮堆叠。

对于单 SKU 补货决策，动作区只保留：

- 生成采购计划

对于运输方案对比，动作区保留：

- 查看 SKU 分析
- 采用推荐方案生成采购计划

对于规则影响模拟，动作区保留：

- 查看影响 SKU
- 打开规则设置

## 7. 流式策略

当前方案不是严格的“卡片流式输出”，而是“流式文本驱动卡片重渲染”。

正式方案建议：

- card 结构化数据由 Tool 返回后一次性稳定展示。
- AI summary / explanation 可以继续流式输出。
- 前端在 Tool 执行期间展示卡片骨架。
- 卡片关键数字不应随着 AI 自然语言逐字输出而反复跳变。

## 8. 约束

- AI 不重新计算采购量、可售天数、断货日期、覆盖需求。
- 所有关键数字来自确定性规则引擎或 Tool 输出。
- 写操作必须二次确认，尤其是 `generate_purchase_plan`。
- 缺失单价、供应商、汇率等字段时，不展示误导性金额，明确标记“待确认”。
